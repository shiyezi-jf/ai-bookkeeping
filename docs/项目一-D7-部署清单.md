## 二、上线架构

```
浏览器
  ├── https://<vercel-app>.vercel.app     前端静态资源（Vite 构建产物）
  └── https://<render-service>.onrender.com/api   后端 FastAPI
                └── /var/data/app.db（Render 持久磁盘）

开发环境：Vite dev server 5173 → /api 代理 → 127.0.0.1:8000
```

关键点：

1. 前端构建时把后端地址写死进产物，所以 **Vercel 必须先知道 Render 的 URL**。
2. 后端只放行 `CORS_ORIGINS` 里的来源，所以 **Render 必须先知道 Vercel 的域名**。
3. 因此顺序固定：先部署后端 → 再部署前端 → 最后回填 CORS → 重启后端。

## 三、后端部署：Render（SQLite + 持久磁盘）

### 3.1 先确认仓库状态

- 代码已推到 GitHub（`render.yaml` 在仓库根目录）。
- `backend/.env`、`app.db`、`frontend/node_modules` 均不会进 Git（根 `.gitignore` 已覆盖）。
- `backend/requirements.txt` 能覆盖所有依赖（fastapi、uvicorn、sqlalchemy、aiosqlite、pydantic-settings、openai）。

### 3.2 用 Blueprint 创建服务

1. 登录 Render → **New** → **Blueprint**。
2. 选择仓库，Render 会自动读取根目录的 `render.yaml`。
3. 创建时会要求填写两个 `sync: false` 的变量：
   - `LLM_API_KEY`：你的大模型密钥。
   - `CORS_ORIGINS`：先填 `http://localhost:5173` 占位，等 Vercel 部署完再改。
4. 点击 **Apply**，等待首次构建完成。

### 3.3 `render.yaml` 关键配置说明

| 配置 | 值 | 说明 |
| --- | --- | --- |
| `rootDir` | `backend` | 只安装后端依赖 |
| `buildCommand` | `pip install -r requirements.txt` | 无需额外构建步骤 |
| `startCommand` | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` | 必须监听平台注入的 `$PORT` |
| `healthCheckPath` | `/api/ping` | 健康检查，返回 `{"message":"pong"}` |
| `disk.mountPath` | `/var/data` | 持久磁盘挂载点 |
| `DATABASE_URL` | `sqlite+aiosqlite:////var/data/app.db` | 注意是 **4 个斜杠**（绝对路径） |
| `plan` | `starter` | 持久磁盘只对付费实例开放 |

> 如果坚持用免费实例：删除 `render.yaml` 里的 `disk` 段，并把 `DATABASE_URL` 改回默认值。代价是每次重启/重新部署数据清空，只适合演示。

### 3.4 部署后验证

```powershell

Invoke-WebRequest "https://<render-service>.onrender.com/api/ping"

# 2. 自动播种是否生效（应为 8 条）
Invoke-WebRequest "https://<render-service>.onrender.com/api/categories"

# 3. 统计接口（budget 应为 3000.00 的预算记录）
Invoke-WebRequest "https://<render-service>.onrender.com/api/stats/monthly"

# 4. 接口文档
Start-Process "https://<render-service>.onrender.com/docs"
```

同时去 Render 的 **Logs** 确认没有启动报错、`/var/data` 下已生成 `app.db`。

### 3.5 环境变量清单

| 变量 | 是否必填 | 值 |
| --- | --- | --- |
| `DATABASE_URL` | 是 | `sqlite+aiosqlite:////var/data/app.db` |
| `CORS_ORIGINS` | 是 | `https://<vercel-app>.vercel.app`（多个用英文逗号） |
| `LLM_API_KEY` | 是 | 你的密钥，只填在平台 |
| `LLM_BASE_URL` | 是 | `https://api.deepseek.com/v1` |
| `LLM_MODEL` | 是 | `deepseek-chat` |
| `PYTHON_VERSION` | 否 | `3.11.10` |

## 四、前端部署：Vercel

1. 登录 Vercel → **Add New** → **Project** → 导入同一个 GitHub 仓库。
2. 项目配置：
   - **Root Directory**：`frontend`
   - **Framework Preset**：Vite（自动识别）
   - **Build Command**：`npm run build`
   - **Output Directory**：`dist`
3. **Environment Variables** 添加：

   | 变量 | 值 |
   | --- | --- |
   | `VITE_API_BASE_URL` | `https://<render-service>.onrender.com/api` |

   > 必须带 `/api` 后缀，否则所有请求会打到后端根路径变成 404。

4. 点击 **Deploy**，拿到形如 `https://xxx.vercel.app` 的域名。

5. 回到 Render，把 `CORS_ORIGINS` 改成 `https://xxx.vercel.app`（保留本地开发可写 `https://xxx.vercel.app,http://localhost:5173`），保存后服务会自动重启。

6. 重新打开前端页面，确认：
   - 列表、图表都有数据；
   - 控制台没有 CORS 报错；
   - Network 里请求地址是 `https://<render-service>.onrender.com/api/...`。

> 预览环境（Preview Deployment）每次域名都不同。若要在 PR 预览里也能用，需要额外把预览域名加入 `CORS_ORIGINS`；不建议为此改成通配符放行。

## 六、常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 线上接口全部 404 | `VITE_API_BASE_URL` 没配或漏了 `/api` | 改 Vercel 环境变量后 **Redeploy**（环境变量改动不会自动生效到旧构建） |
| 控制台 CORS 报错 | `CORS_ORIGINS` 没包含当前前端域名 | 回填 Render 环境变量并保存重启 |
| 首次访问很慢 | 免费/低配实例冷启动 | 属正常现象，README 里写清楚 |
| 重启后数据没了 | 用了免费实例、没有持久磁盘 | 换 `starter` + 磁盘，或把 `DATABASE_URL` 指到磁盘路径 |
| 接口 500 且日志提示数据库锁定 | 多 worker 并发写 SQLite | 保持单 worker（`uvicorn` 默认 1 个） |
| 后端日志提示 `LLM_API_KEY` 空 | 环境变量没填或填错位置 | 在 Render 的 Environment 里补 |
| 改完环境变量页面没变化 | Vercel 未重新构建 | 手动 Redeploy |

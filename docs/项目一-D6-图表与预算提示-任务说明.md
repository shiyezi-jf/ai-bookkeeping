## 四、接口契约（必须严格遵守）

### 4.1 `GET /api/categories` —— 分类字典

**请求参数**：无。

**响应**：`CategoryRead` 数组，按 `id` 升序。

```json
[
  { "id": 1, "name": "餐饮", "icon": "food", "color": "#F97316" }
]
```

**约束**

1. 必须返回 `color`，前端饼图配色以此为准，**前端不得另写一份颜色常量**。
2. `icon`、`color` 允许为 `null`（表中字段可空），前端需有兜底颜色。

### 4.2 `GET /api/stats/monthly` —— 月度统计

**请求参数**

| 参数 | 类型 | 必填 | 默认 | 约束 |
| --- | --- | --- | --- | --- |
| `month` | str | 否 | 当前自然月 | 格式 `YYYY-MM`；非法格式返回 `400` |

**响应结构**

```json
{
  "month": "2026-11",
  "summary": [
    { "category": "餐饮", "amount": "123.50", "count": 3 },
    { "category": "交通", "amount": "35.00", "count": 1 }
  ],
  "trend": [
    { "month": "2026-06", "amount": "0.00" },
    { "month": "2026-07", "amount": "0.00" },
    { "month": "2026-08", "amount": "88.00" },
    { "month": "2026-09", "amount": "0.00" },
    { "month": "2026-10", "amount": "21.00" },
    { "month": "2026-11", "amount": "158.50" }
  ],
  "budget": {
    "amount": "3000.00",
    "spent": "158.50",
    "exceeded": false
  }
}
```

**三块数据的计算规则**

| 块 | 规则 |
| --- | --- |
| `summary` | 筛选 `occurred_on ∈ [当月 1 日, 次月 1 日)`；按 `category` 分组；`SUM(amount)`、`COUNT(*)`；**按金额从大到小排序** |
| `trend` | 以所选月份为终点，向前取 **6 个自然月**（含终点月）；每月金额为该月 `SUM(amount)`；**无数据的月份必须补 `amount = "0.00"`**，顺序为从早到晚 |
| `budget` | 取 `budgets` 表中 `month = 所选月份` 且 `category_id IS NULL` 的记录；`spent` = 该月总支出；`exceeded = spent > amount` |

**关键约束**

1. `summary` 与 `trend` 的月度边界必须使用**日期范围比较**（`>= 当月 1 日 AND < 次月 1 日`），禁止用 `LIKE` 拼接字符串。
2. 趋势分组可用 SQLite 的 `strftime('%Y-%m', occurred_on)`；此处与筛选场景不同——**筛选用范围（走索引），分组用函数（本就要全扫）**。
3. `trend` 的 6 个月骨架必须由后端生成并补零；**SQL 只返回有数据的月份，直接使用会导致 X 轴缺失月份、折线错位**。
4. 月份回退必须正确处理跨年：`2026-01` 的前一个月是 `2025-12`。
5. 若该月不存在预算记录，`budget` 返回 `null`，前端不展示预算提示（**不得返回 `amount = 0` 冒充预算**）。
6. 金额一律为字符串化的两位小数（与现有 `Decimal` 序列化行为一致），前端不做浮点运算。

**错误响应**

| 场景 | 状态码 |
| --- | --- |
| `month` 格式非法（如 `2026-13`、`abc`） | `400` |

### 4.3 预算播种规则

在 `main.py` 的 `lifespan` 中执行：

1. 计算当前自然月（`YYYY-MM`）。
2. 查询 `budgets` 中是否存在 `month = 当前月` 且 `category_id IS NULL` 的记录。
3. 不存在则插入一条，金额为 **3000.00**；已存在则跳过（**必须幂等，不得重复插入**）。

**已知限制（写入 README）**：预算只在应用启动时播种。若服务跨月长期运行，新月不会自动获得预算，需重启或手动插入。这是本轮有意接受的简化。

**改动文件**

- `backend/app/routers/stats.py`：新增 `GET /api/stats/monthly`

**交付要求**

- 趋势补零必须在后端完成。
- 预算缺失时返回 `null`。

**实现提示（不给完整代码）**

1. **分类汇总**：`select(Transaction.category, func.sum(...), func.count()).where(范围).group_by(...).order_by(金额降序)`
2. **趋势**：先用 Python 生成"过去 6 个月的 `YYYY-MM` 列表"，再一次性查出这 6 个月的数据（`strftime` 分组），最后按列表填零。
3. **月份回退**：写一个"上一个月"的纯函数，注意 1 月要退到上一年 12 月；单独测它比测接口快。
4. **预算**：一条 `select(Budget).where(month == m, category_id.is_(None))`。

## 八、完成定义（Definition of Done）

D6 完成的唯一标准是能回答：

1. **为什么统计必须由后端做？** 结合分页场景说明前端算会错在哪。
2. **趋势为什么要补零？** 不补会导致什么现象？
3. **饼图的内外半径由 option 的哪一行控制？** 把环形改成实心饼要改哪里？
4. **编辑一条金额后，数据是怎样流到两张图上的？** 说出完整链路（从 `PATCH` 成功到 `setOption`）。

仅图表能显示但讲不清以上四点，视为未完成。

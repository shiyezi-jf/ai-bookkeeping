## 开始之前：先认识几个词

下面这些词在后面的步骤里会反复出现。**你不用记住，卡住时回来查表就行。**

| 你会看到的词                      | 用大白话说就是                     | 打个比方             |
| --------------------------- | --------------------------- | ---------------- |
| 仓库 / Repository / Repo      | 你放在 GitHub 上的那个代码文件夹        | 一个网盘文件夹，但能记录每次改动 |
| 提交 / commit                 | 把改动"存一次档"                   | 游戏存档             |
| 推送 / push                   | 把本机的存档上传到网盘                 | 把存档同步到云          |
| 部署 / Deploy                 | 让平台把你的代码跑起来，变成一个能访问的网址      | 把菜做好端上桌          |
| 构建 / Build                  | 平台把你的代码"加工"成能运行的东西          | 把面粉做成面包          |
| 环境变量 / Environment Variable | 不写在代码里、只填在平台后台的几行设置，比如密钥    | 保险箱密码，不写在门上      |
| 实例 / Instance               | 平台分给你的那台"虚拟电脑"              | 租来的一间小屋          |
| 域名 / URL                    | 网址                          | 门牌号              |
| API Key / 密钥                | 调用大模型时要出示的一串密码              | 一张充值卡卡号          |
| CORS                        | 浏览器的一条安全规矩：前端网址必须先被后端"点名允许" | 门卫手里的访客名单        |
| 日志 / Logs                   | 平台记录的程序运行流水账                | 监控录像             |

**这张表里最重要的是"环境变量"和"CORS"**，整个部署过程中 80% 的失败都出在这两个词上。

## 整体路线图（先看一遍，心里有数）

```
第 1 阶段  出发前检查      确认本地能跑、代码已在 GitHub    约 10 分钟
     ↓
第 2 阶段  后端上线        部署到 Render，拿到一个后端网址   约 25 分钟（含等待）
     ↓
第 3 阶段  前端上线        部署到 Vercel，拿到最终网址       约 20 分钟（含等待）
     ↓
第 4 阶段  收尾            截图、写 README、逐条验收         约 25 分钟
```

**顺序不能换。** 原因很实在：前端在"构建"的那一刻，必须把后端网址写死进代码里；后端又必须知道前端网址才能放行。所以只能"先有后端地址 → 再做前端 → 最后把前端地址告诉后端"。

## 第 1 阶段 · 出发前检查

> 这一阶段只做三件事：确认工具都在、确认本地能跑、确认代码已经在 GitHub 上。  
> **为什么要先做**：如果本地都跑不起来，线上出问题时你分不清是代码的问题还是平台的问题，会非常痛苦。

---

### 第 1 步 · 打开一个"能敲命令的窗口"

**你要做什么**：打开终端（就是那个黑框框，可以输入文字命令的地方）。

**动手**：

1. 按键盘 `Win` 键（就是左下角有窗户图标的键），输入 `Git Bash`。
2. 在搜索结果里点击 **Git Bash**，会弹出一个黑底白字的窗口。
3. 在弹出的窗口里，输入下面这一行，然后按回车：

```bash
git --version
```

**你应该看到**：窗口里出现类似这样的一行字：

```
git version 2.55.0.windows.3
```

**✅ 本步通过标准**：只要出现 `git version` 开头、后面跟一串数字，就算通过。数字和你不一样完全没关系。

**⚠️ 卡住了怎么办**：

- 搜不到 Git Bash → 说明电脑没装 Git。打开 <https://git-scm.com/download/win> ，点 **Click here to download**，下载完双击安装，**一路点 Next 到最后 Finish**，不用改任何选项。装完关掉所有黑窗口，重新做第 1 步。

---

### 第 2 步 · 进入你的项目文件夹

**你要做什么**：把黑窗口"站到"项目文件夹里。

**动手**：在黑窗口里输入下面这一行（**可以直接复制粘贴**，在 Git Bash 里粘贴用鼠标右键 → Paste，或按 `Shift + Insert`），然后回车：

```bash
cd /d/Code/My_Project/ai-bookkeeping
```

再输入下面这行并回车，看看里面有什么：

```bash
ls
```

**你应该看到**：窗口里列出这些名字（顺序可能不同）：

```
backend   docs   frontend   render.yaml
```

**✅ 本步通过标准**：能看到 `backend`、`frontend`、`render.yaml` 这三个名字。这说明你站对地方了。

**⚠️ 卡住了怎么办**：

- 提示 `No such file or directory` → 说明路径不对。在文件资源管理器里找到 `ai-bookkeeping` 文件夹，**在文件夹空白处按住 Shift 点鼠标右键**，选 **Open Git Bash here**，这样打开的窗口天生就在正确位置，直接做第 3 步。
- 提示 `Permission denied` → 检查是不是把 `cd` 打成了别的字母。

---

### 第 3 步 · 确认本地项目是能跑的

**你要做什么**：在本地把后端和前端各启动一次，确认没坏。**不用改任何代码。**

**动手（先启动后端）**：在黑窗口里依次输入下面三行，每输入一行按一次回车：

```bash
cd backend
source .venv/Scripts/activate
python -m uvicorn app.main:app --reload --port 8000
```

> 第 2 行是"进入项目的虚拟环境"，第 3 行是"启动后端服务"。  
> 启动后这个窗口会被"占住"，这是正常的——它正在干活，不能关。

**你应该看到**：最后几行里有一句：

```
Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

**动手（验证后端）**：**不要关这个窗口**，另外打开一个浏览器标签页，在地址栏输入下面这个地址并回车：

```
http://127.0.0.1:8000/api/ping
```

**你应该看到**：页面上显示一行字：

```json
{"message":"pong"}
```

**动手（再启动前端）**：回到 Git Bash 窗口，**不要关掉后端那个**。再开一个新的 Git Bash（重复第 1 步），输入：

```bash
cd /d/Code/My_Project/ai-bookkeeping/frontend
npm run dev
```

**你应该看到**：出现类似这样的一段：

```
  VITE v8.x.x  ready in 400 ms
  ➜  Local:   http://localhost:5173/
```

**动手（验证前端）**：浏览器新开一个标签页，输入 `http://localhost:5173` 回车。

**你应该看到**：记账页面正常显示——顶部有输入框和"解析"按钮，下面是账单列表和两张图表。

**✅ 本步通过标准**（三条全中才算通过）：

1. `http://127.0.0.1:8000/api/ping` 显示 `{"message":"pong"}`
2. `http://localhost:5173` 页面能打开、样式正常
3. 页面上能看到分类饼图（哪怕是空的）和趋势折线图

**⚠️ 卡住了怎么办**：

| 现象                          | 原因        | 怎么办                                |
| --------------------------- | --------- | ---------------------------------- |
| `python: command not found` | 虚拟环境没激活成功 | 确认第 2 行命令执行后，命令行开头出现了 `(.venv)` 字样 |
| 端口 8000 已被占用                | 之前启动过后端没关 | 在黑窗口按 `Ctrl + C` 停掉旧的，再重新启动        |
| 页面能开但数据全空、控制台报错             | 后端没启动     | 回到第 3 步，先把后端那个窗口跑起来                |

**做完这一步请把两个黑窗口都按 `Ctrl + C` 停掉，然后关掉。** 本地检查到此结束，后面全部在网页上操作。

---

### 第 4 步 · 确认代码已经躺在 GitHub 上

**你要做什么**：确认 GitHub 上那个仓库里，有你最新的代码。

**动手**：新开一个 Git Bash，执行：

```bash
cd /d/Code/My_Project/ai-bookkeeping
git status
```

**你应该看到**：其中有这么一句：

```
nothing to commit, working tree clean
```

**动手（再去网页确认）**：打开浏览器，在地址栏输入并回车：

```
https://github.com/shiyezi-jf/ai-bookkeeping
```

**你应该看到**：GitHub 页面上能看到这几个条目：

```
backend    docs    frontend    .gitignore    render.yaml
```

点一下 `render.yaml` 这个名字，页面里应该显示一段以 `services:` 开头的文字。

**✅ 本步通过标准**：

1. 本地 `git status` 显示 `nothing to commit, working tree clean`
2. GitHub 网页上能看到 `render.yaml` 这个文件，点进去有内容

**⚠️ 卡住了怎么办**：

| 现象                     | 怎么办                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `git status` 显示一堆红色文件名 | 说明有改动没上传。依次执行 `git add .` → `git commit -m "部署前提交"` → `git push`，再重新检查                                                               |
| GitHub 网页 404          | 说明仓库是私有的且你没登录，或者仓库名拼错。先登录 GitHub 再访问                                                                                                 |
| `git push` 要求输入账号密码    | 密码要填 **Personal Access Token**（在 GitHub 头像 → Settings → Developer settings → Personal access tokens 里生成），不是登录密码。如果之前 push 成功过，一般不会再问 |

> 📌 **这一步是整个部署的"地基"**。后面 Render 和 Vercel 都是直接从 GitHub 上"拿货"的——GitHub 上没有的代码，线上一定没有。所以这一步必须确认干净。

## 第 2 阶段 · 后端上线（Render）

> 这一阶段的目标：让你的后端程序在互联网上跑起来，拿到一个形如  
> `https://ai-bookkeeping-api.onrender.com` 的网址。
>
> **为什么先做后端**：因为前端在"构建"时要把后端网址写死进去。所以必须先有后端地址。

---

### 第 5 步 · 拿到大模型密钥（API Key）

**你要做什么**：去 DeepSeek 官网申请一串密钥。**没有它，"一句话记账"这个功能在线上就是死的**（其他功能正常，但点"解析"会失败）。

> 如果你本地 `.env` 里已经有一串能用的 `sk-` 开头的密钥，**可以跳过这一步直接去第 6 步**，到时候把它填进 Render 就行。

**动手**：

1. 浏览器打开 `https://platform.deepseek.com`。
2. 点右上角 **登录 / Sign in**，用手机号注册并登录。
3. 登录后，看左侧菜单，找到 **API keys**（有的界面叫 **API 密钥**），点进去。
4. 点页面上的 **创建 API key**（或 **Create new API key**）按钮。
5. 弹出的输入框里随便起个名字，比如填 `ai-bookkeeping`，然后确认。
6. 页面会显示一串以 `sk-` 开头、很长很长的字符。

**你应该看到**：一串类似 `sk-3f8a9c...（后面还有几十位）` 的字符。

**✅ 本步通过标准**：

1. 你手上有一串以 `sk-` 开头的字符
2. 这串字符已经**粘贴保存到本地的记事本里**（新建一个 txt 文件放着）

**⚠️ 卡住了怎么办**：

| 现象              | 怎么办                                              |
| --------------- | ------------------------------------------------ |
| 页面提示余额不足 / 无法调用 | 点左侧 **充值**，充最小金额（10 元就够测试很久），到账后再创建 key          |
| 关掉页面后密钥不见了      | **密钥只在创建时显示一次**，关掉就再也看不到。回第 4 步重新创建一个新的即可，旧的可以删掉 |

> 🔴 **极其重要的一条**：这串 `sk-` 开头的字符**绝对不能写进代码、绝对不能提交到 GitHub**。一旦泄露，别人可以用你的钱调用大模型。本项目已经用 `.gitignore` 挡住了 `.env` 文件，你只要"只往平台后台填、不往文件里写"就安全。

### 第 6 步 · 注册 Render 账号

**你要做什么**：注册后端托管平台 Render 的账号。

**动手**：

1. 浏览器打开 `https://render.com`。
2. 点右上角 **Get Started**（或 **Sign Up**）。
3. 在注册页面选择 **GitHub** 这个按钮（意思是"用 GitHub 账号登录"，这样后面它能直接读你的代码）。
4. 弹出 GitHub 授权页面，点绿色的 **Authorize Render** 按钮。
5. 如果要求输入密码，输入你 GitHub 的登录密码。
6. 可能会让你填邮箱，填一个你能收到邮件的邮箱，然后去邮箱点验证链接。

**你应该看到**：进入 Render 的后台首页，页面顶部有 **New +** 之类的按钮，说明登录成功了。

**✅ 本步通过标准**：能看到 Render 的控制台首页（一排菜单/按钮），而不是登录页。

**⚠️ 卡住了怎么办**：

- 授权页面点了没反应 → 关掉弹窗，回 Render 首页重新点一次 **GitHub** 登录。
- 提示邮箱未验证 → 去邮箱找 Render 发来的邮件（可能在垃圾箱），点里面的 **Verify** 链接。

| **B · 付费**         | 约 7 美元 | 数据永久保留               | 你真的打算长期记账      |

> **建议**：先走 A 把整个流程跑通，确认一切正常后，如果想让数据长期留着，再按附录 A 换成 B。换的时候只需要改一行，不用重做。

#### 如果你选 A（免费）：按下面 6 小步改文件

**① 打开文件**

1. 打开"文件资源管理器"，进到 `D:\Code\My_Project\ai-bookkeeping`。
2. 找到 `render.yaml` 这个文件，**右键 → 打开方式 → 记事本**。

**② 全选并删除旧内容**

在记事本里按 `Ctrl + A`（全选），再按 `Delete`（删除）。窗口应该变成一片空白。

**③ 把下面这一整段粘贴进去**

复制下面框里的**全部内容**（从第一行 `services:` 到最后一行 `deepseek-chat`），粘贴到记事本里：

```yaml
services:
  - type: web
    name: ai-bookkeeping-api
    runtime: python
    plan: free
    rootDir: backend
    buildCommand: pip install -r requirements.txt
    startCommand: uvicorn app.main:app --host 0.0.0.0 --port $PORT
    healthCheckPath: /api/ping
    envVars:
      - key: PYTHON_VERSION
        value: "3.11.10"
      - key: DATABASE_URL
        value: sqlite+aiosqlite:///./app.db
      - key: CORS_ORIGINS
        sync: false
      - key: LLM_API_KEY
        sync: false
      - key: LLM_BASE_URL
        value: https://api.deepseek.com/v1
      - key: LLM_MODEL
        value: deepseek-chat
```

> **粘贴后请仔细核对这几点**（错了会部署失败）：
>
> - 每一行的**缩进是空格，不是 Tab**。如果你是从网页复制的，通常没问题；如果自己敲，请用空格。
> - `plan: free` 这一行在，并且**没有** `disk:` 那一段。
> - `DATABASE_URL` 后面是 **3 个斜杠**：`sqlite+aiosqlite:///./app.db`。
> - `PYTHON_VERSION` 的值 `3.11.10` **必须带英文双引号**。

**④ 保存**

按 `Ctrl + S`。如果弹出"另存为"窗口，说明你打开的方式不对（可能打开了别的文件），取消后重新按 ① 操作。

**⑤ 上传到 GitHub**

回到 Git Bash，依次执行这三行（每行按一次回车）：

```bash
cd /d/Code/My_Project/ai-bookkeeping
git add render.yaml
git commit -m "改用免费实例部署"
git push
```

**你应该看到**：`git push` 后出现类似 `main -> main` 的字样。

**⑥ 确认真的传上去了**

浏览器打开 `https://github.com/shiyezi-jf/ai-bookkeeping/blob/main/render.yaml`，页面上应该能看到 `plan: free` 这一行，并且**看不到** `disk:` 这个词。

### 第 8 步 · 在 Render 上创建后端服务

**你要做什么**：让 Render 读取你仓库里的 `render.yaml`，自动建好一台"虚拟电脑"并把后端跑起来。

**动手**：

1. 打开 `https://dashboard.render.com`（已登录状态）。
2. 点页面右上角的 **New +** 按钮（有的界面显示为 **New**）。
3. 在下拉菜单里点 **Blueprint**。
   > 菜单里会有 Web Service、Static Site、Postgres 等选项，**不要选错，一定是 Blueprint**。Blueprint 的意思是"按照仓库里的配置文件自动建"，比手动建省事得多。
4. 如果第一次用，页面会让你连接 GitHub：
   - 点 **Connect GitHub** → 弹窗里选 **Only select repositories**（只授权这一个仓库，更安全）→ 在下拉里勾选 **ai-bookkeeping** → 点 **Install & Authorize**。
5. 回到 Render 页面，在仓库列表里点 **ai-bookkeeping** 右边的 **Connect**。
6. 页面会显示 Blueprint 名称（默认 `ai-bookkeeping` 之类），不用改。
7. 下面会出现一个**要求你填值的表单**，通常有两条，标题分别是 `CORS_ORIGINS` 和 `LLM_API_KEY`。**逐条填**：
   | 变量名            | 填什么                     | 说明                     |
   | -------------- | ----------------------- | ---------------------- |
   | `CORS_ORIGINS` | `http://localhost:5173` | 先填这个占位，第 11 步会回来改成真实网址 |
   | `LLM_API_KEY`  | 你第 5 步拿到的那串 `sk-` 开头的密钥 | 原样粘贴，前后不要有空格           |
   > 如果表单里还出现了 `DATABASE_URL`、`LLM_BASE_URL`、`LLM_MODEL`，说明配置文件被改错了（它们应该是固定值，不该让你填）。回第 7 步检查文件内容。
8. 点页面底部的 **Apply**（或 **Deploy Blueprint**）按钮。

**你应该看到**：页面跳转到一个服务详情页，顶部有一个状态标签，先是 **Deploying**（部署中，黄色或蓝色），右上角有 **Logs**（日志）标签。

**✅ 本步通过标准**：页面进入"部署中"状态，并且能在 **Logs** 里看到滚动的文字。**这时候还不需要通过，只是确认它开始干活了。**

**⚠️ 卡住了怎么办**：

| 现象                          | 原因               | 怎么办                                            |
| --------------------------- | ---------------- | ---------------------------------------------- |
| 找不到 **Blueprint** 选项        | 账号未完成验证          | 检查邮箱里的验证邮件；或在 Render 首页点 **Get Started** 重新走一遍 |
| 提示 `render.yaml not found`  | 仓库里没有这个文件，或不在根目录 | 回第 4 步确认 GitHub 网页上能看到 `render.yaml`           |
| 提示 `Invalid plan`               | 配置文件里写了平台不认识的套餐名 | 回第 7 步，严格照抄那份内容                                |
| 要求绑定银行卡（**即使已改成免费版**） | Render 的账号级风控验证，与 `plan` 无关 | 见下方「关于绑卡」，绑卡后免费实例不扣费                    |
| 表单里没有 `LLM_API_KEY` 这一项     | 配置文件改坏了          | 回第 7 步，严格照抄那份内容                                |

#### 关于绑卡（很多人卡在这里，单独说清楚）

**先把结论说明白**：配置文件写成 `plan: free` **不能**免除绑卡这一步。这不是"你选错了套餐"，而是 Render 对部分新账号（新注册、非欧美地区尤其常见）要求先添加支付方式才允许创建服务——它是一道**账号级的身份验证**，跟你要建免费还是付费服务无关。所以你会遇到"明明是免费版，还是让我填卡"。

- **免费实例不会产生费用**。填卡时可能看到 `$1` 的预授权（临时冻结，用于验证卡是否有效），通常几天内自动解除，不会真的扣钱。
- **绑卡入口**：点页面右上角（或左下角）你的头像 → **Billing** → **Add Payment Method** → 填卡号、有效期、CVV → 保存。
- **绑完不要重新建 Blueprint**：回到刚才那个 Blueprint 页面，直接再点一次 **Apply** 就行。
- **卡片要求**：支持国际支付的 **Visa / Mastercard**。国内多数银行的**双币/全币种信用卡**可以，纯银联单币卡通常不行，预付卡、部分虚拟卡也常被拒。
- **绑完还弹**：① 换一个无痕窗口重开 `dashboard.render.com`；② 确认绑卡的 workspace 和你建服务的 workspace 是同一个（Render 的支付方式是绑在 **workspace** 上的，不是绑在账号上，右上角可以切换 workspace 查看）。
- **确实无法绑卡**：这条路走不通，换平台比硬扛省时间。备选见文末「附录 E」。

### 第 12 步 · 填环境变量，然后点 Deploy

**你要做什么**：把后端网址告诉前端，然后开始构建。

> **为什么必须填**：前端代码里写的是"请求 `/api/xxx`"。在本地，Vite 会把这个请求转发到 8000 端口；但线上没有这个转发，必须直接指向你的 Render 网址。这个值会在"构建"时被写死进代码，所以**现在填、填对，否则整个页面拿不到数据**。

**动手**：

1. 在同一个 **Configure Project** 页面，往下找到 **Environment Variables**（环境变量）区域。
2. 点 **Add** 或直接在两个输入框里填：
   | 左边的 Name（变量名）       | 右边的 Value（值）                                  |
   | ------------------- | --------------------------------------------- |
   | `VITE_API_BASE_URL` | `https://ai-bookkeeping-api.onrender.com/api` |
   **值的写法有三个必须注意的地方**：
   - 用你**第 9 步记下来的那个真实后端网址**，不要照抄我这里的示例。
   - 结尾**必须有 `/api`**。少了它，所有请求会打到后端首页，全部 404。
   - 结尾**不要有斜杠**，不要写成 `.../api/`。
   - 前后**不要有空格**。
   正确的例子：`https://ai-bookkeeping-api.onrender.com/api`  
   错误的例子：`https://ai-bookkeeping-api.onrender.com`（少了 /api）  
   错误的例子：`https://ai-bookkeeping-api.onrender.com/api/`（多了斜杠）
3. 点页面底部的 **Deploy** 按钮。

**你应该看到**：页面跳到一个构建动画页面，中间是 Vercel 的三角形标志，下面一行行出现：


**动手**：点 **Continue to Dashboard**，在 **Domains** 区域找到你的网址，形如：

### 第 13 步 · 让前后端"互相认识"（回填 CORS）

**你要做什么**：回到 Render，把你刚拿到的 Vercel 网址加进"允许访问名单"。

> **为什么必须做**：浏览器有一条安全规矩——前端在 A 网址，后端在 B 网址，后端必须明确说"我允许 A 来访问"，否则浏览器会拦截请求。**这一步没做，页面能打开，但所有数据都是空的，控制台会红一片。**
>
> 这是整个部署里**最典型的"看起来成功了其实是假成功"**&#x7684;坑，务必做完并验证。

**动手**：

1. 回到 Render 后台 `https://dashboard.render.com`，点进你的 **ai-bookkeeping-api** 服务。
2. 点左侧菜单的 **Environment**（环境变量）。
3. 找到 `CORS_ORIGINS` 这一行，点它右边的 **编辑** 图标（铅笔形状），或直接点值的位置进入编辑。
4. 把值从 `http://localhost:5173` 改成下面这样（**用你自己的 Vercel 网址**）：

```
https://ai-bookkeeping.vercel.app,http://localhost:5173
```

格式说明：

- 两个网址之间用**英文逗号**隔开，**不能有空格**。
- 第一个是你线上的前端网址（**不要带结尾的斜杠**）。
- 第二个 `http://localhost:5173` 保留着，方便你以后本地开发时还能用。

1. 点 **Save Changes**（保存更改）。

**你应该看到**：页面提示保存成功，服务会自动开始重新部署（状态又变回 **Deploying**），顶部可能显示 "Deploying new version"。

**动手**：等 2–4 分钟，直到状态重新变回绿色 **Live**。

**✅ 本步通过标准**：

1. `CORS_ORIGINS` 的值里，**同时**包含你的 `https://xxx.vercel.app` 和 `http://localhost:5173`
2. 服务状态重新变回 **Live**

**⚠️ 卡住了怎么办**：

| 现象        | 怎么办                                                     |
| --------- | ------------------------------------------------------- |
| 保存后状态一直没变 | 手动点页面右上角的 **Manual Deploy → Deploy latest commit** 触发一次 |
| 不知道值有没有生效 | 打开 `https://你的后端网址/api/ping`，能返回 pong 就说明服务活着           |

## 附录 A · 付费版配置（数据永久保留）

**什么时候用**：你已经跑通免费版，并且希望记的账不会因为重新部署而消失。

**代价**：Render 的 Starter 实例约 7 美元/月，需要在 Render 后台 **Billing** 里绑定银行卡。

**怎么切**：把 `render.yaml` 整份替换成下面内容，然后 `git add render.yaml && git commit -m "改用付费实例+持久磁盘" && git push`。Render 会自动检测到变化并重新部署。

```yaml
services:
  - type: web
    name: ai-bookkeeping-api
    runtime: python
    plan: starter
    rootDir: backend
    buildCommand: pip install -r requirements.txt
    startCommand: uvicorn app.main:app --host 0.0.0.0 --port $PORT
    healthCheckPath: /api/ping
    disk:
      name: sqlite-data
      mountPath: /var/data
      sizeGB: 1
    envVars:
      - key: PYTHON_VERSION
        value: "3.11.10"
      - key: DATABASE_URL
        value: sqlite+aiosqlite:////var/data/app.db
      - key: CORS_ORIGINS
        sync: false
      - key: LLM_API_KEY
        sync: false
      - key: LLM_BASE_URL
        value: https://api.deepseek.com/v1
      - key: LLM_MODEL
        value: deepseek-chat
```

**和免费版只有 3 处不同**（理解这 3 处，你就明白为什么要多花钱）：

1. `plan: starter`（换成付费实例）
2. 多了 `disk:` 那 4 行（挂一块"不会被清空的硬盘"）
3. `DATABASE_URL` 变成 **4 个斜杠** `////var/data/app.db`（指向那块硬盘的绝对路径）

> ⚠️ 切换后，**之前免费版记的账不会自动搬过来**（数据库文件在两台不同的机器上）。切换前如果想保留数据，先用页面把数据截图留档。

**不要凭感觉乱点。** 平台后台的每个按钮都有后果，点错一次可能要多花 20 分钟。

做到第 17 步的 20 条全部打勾，D7 就结束了。**这时候你手上有的不只是一个能打开的网址，而是"我能把一个东西从自己电脑搬到互联网上"这个能力**——这个能力比这个项目本身值钱。

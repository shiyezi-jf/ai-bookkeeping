## 第 0 章 开工前：AI 协作规程

> 这一章比后面所有技术内容都重要。项目做不完可以补，习惯坏了补不回来。

### 0.1 唯一判断标准

面对任何一段代码，问自己一句话：

> **这段代码，我能不能在没有任何辅助的情况下重写一遍，并解释每一行为什么这么写？**

- **能** → 交给 AI 写，节省时间。
- **不能** → 自己敲。

判断依据不是代码量，而&#x662F;**"你将来还要不要靠它吃饭"**。

### 0.2 三层分工（本项目的具体划分）

| 层级      | 处理方式               | 本项目具体范围                                                                                              | AI 占比  |
| ------- | ------------------ | ---------------------------------------------------------------------------------------------------- | ------ |
| **肌肉层** | 自己敲，禁止 AI 生成       | 表结构与字段类型、`/api/parse` 解析链路、Pydantic 校验与重试、`/api/transactions` 路由与事务、统计 SQL 的 `GROUP BY`、**报错的第一次诊断** | 0–20%  |
| **胶水层** | AI 生成 → 逐行读懂 → 改一处 | axios 封装、ECharts 配置项、Element Plus 表单与弹窗、分页/筛选样板、Pinia store 骨架                                       | 40–50% |
| **盲区层** | 直接用 AI，只做验证        | 依赖版本冲突、`vite.config.ts` 的 proxy、CORS 配置、Dockerfile / 部署配置、冷门 API 用法                                  | 70–80% |

**为什么肌肉层必须自己敲**：`amount` 字段如果写成 `Float`，测试时看不出问题，等攒到几百条记录发现总额差几毛钱，你连从哪查都不知道。这类错误 AI 会犯，而且你**看不出来**——因为你还没建立"这里容易错"的直觉。直觉只能靠手敲建立。

### 0.3 三条铁律

**铁律一：报错先自己看 5 分钟，再看不懂才问 AI。**

具体动作：

1. 读堆栈的**最后一行**——那才是真正的错误类型和消息。
2. 从下往上找**第一个出现在你自己文件里**的行号，那就是案发现场。
3. 看那一行的变量值，猜一个原因，然后验证。

AI 该在你"看不懂"时介入，不该在你"不想看"时介入。这条守不住，三个月后你会有个项目，但没有任何能力。

**铁律二：拿到代码，关掉 AI，用自己的话复述一遍。**

说不出来 = 没学会。这段必须删掉自己重敲。复述的标准是能说清"这行在干什么、为什么不能删、换成另一种写法会怎样"。

**铁律三：每段 AI 代码，你都得能删掉重写。**

删了就再也写不出来，这个模块等于没做——而且面试官一定挑这种地方问。

### 0.4 四段式提问模板

大多数人用 AI 失败，不是因为用了 AI，而是**提问方式让 AI 替你思考了**。

#### 先看反例

> ❌ "用 FastAPI 写一个记账的增删改查"

你拿到 200 行能跑的代码，但你对它一无所知。这叫**代写**，不叫开发。

#### 正确模板

```
【1. 我现在有什么】
技术栈 + 已有文件路径 + 关键代码片段（贴 10 行代码比描述 100 字有用）

【2. 我要达成什么】
具体到接口路径、字段、行为

【3. 我卡在哪】
报错原文（完整堆栈，别截断）+ 我试过什么 + 结果如何

【4. 我要你怎么答】
先给思路不给代码 / 给代码但逐行注释 / 只给最小可运行片段 / 只列问题不要重写
```

**第 4 段是九成人不写的，但它最关键。** 你要求它"只给思路"，你就必须自己写——**学习的发生点就在这一步**。

#### 本项目三个真实场景的示范

**场景 A · 学概念（自己敲之前先搞清楚方向）**

> 我在用 FastAPI + SQLAlchemy 2.x 异步 + SQLite 做记账项目。现在要查某个月的所有账单并按分类汇总金额。  
> 我想知道：应该用 `select()` 还是 `session.query()`？异步下 `GROUP BY` 聚合的返回值结构是什么样？  
> **只给我思路和关键函数签名，不要给完整代码**，我自己写。

**场景 B · 卡报错（先自己看了 5 分钟再来）**

> 环境：FastAPI + SQLAlchemy 异步 + aiosqlite。  
> 报错：`MissingGreenlet: greenlet_spawn has not been called; can't call await_only() here`  
> 完整堆栈：【粘贴】  
> 我的代码【贴出出错的 10 行】。我试过在那一行加 `await`，报错变成 `object NoneType can't be used in 'await' expression`。  
> **请先告诉我这个错一般在什么情况下发生，再指出我代码里哪一行触发的**，不要直接给我改好的代码。

**场景 C · 求 review（最高性价比的用法）**

> 这是我写的 `/api/parse` 路由【贴代码】。请从三个角度 review：
>
> 1. 异常处理有没有漏掉的分支
> 2. 有没有阻塞事件循环的地方
> 3. Pydantic 校验够不够严，模型返回脏数据时会不会漏进数据库  
>    **不要重写，只列问题和我该想的方向。**

> 💡 **场景 C 是整份文档里最值钱的用法**。你写完贴过去问"这段有什么问题"，比让它写十段收获大得多。

### 0.5 绝对不能交给 AI 的四样东西

| # | 内容            | 原因                                                 |
| - | ------------- | -------------------------------------------------- |
| 1 | **项目 README** | 面试官真的会翻 GitHub。AI 写的 README 有很明显的塑料味（"本项目致力于打造……"） |
| 2 | **你对项目的解释**   | 面试现场没有 AI                                          |
| 3 | **简历上的数字**    | 编的一问就穿                                             |
| 4 | **报错的第一次诊断**  | 这是最值钱的肌肉，练的就是这个                                    |

### 0.6 每日 AI 占比参考

| 天  | 内容     | AI 占比 | 说明                                  |
| -- | ------ | ----- | ----------------------------------- |
| D1 | 搭骨架    | 20%   | 唯一目的不是"写出功能"，而是建立"我能掌控这东西"的感觉       |

## 第 2 章 技术栈

### 2.1 后端

| 选型                | 版本     | 用途          | 为什么选它                                    |
| ----------------- | ------ | ----------- | ---------------------------------------- |
| Python            | 3.11+  | 运行时         | 3.11 起 async 性能明显改善，且 `tomllib` 等标准库更全   |
| FastAPI           | 0.110+ | Web 框架      | 自动生成 OpenAPI 文档（`/docs`），前后端联调省一半沟通成本    |
| Uvicorn           | 0.27+  | ASGI 服务器    | 开发期 `--reload` 热重载                       |
| SQLAlchemy        | 2.0+   | ORM         | 2.0 风格统一了同步/异步 API，且是事实标准                |
| aiosqlite         | 0.19+  | SQLite 异步驱动 | 配合 `sqlite+aiosqlite:///` 使用             |
| Pydantic          | 2.x    | 数据校验        | v2 的 `model_validate_json` 正好用来校验 LLM 输出 |
| pydantic-settings | 2.x    | 配置管理        | 从 `.env` 读密钥，不硬编码                        |
| httpx             | 0.27+  | 异步 HTTP     | 调 LLM 用（若不用 SDK）                         |
| openai            | 1.x    | LLM SDK     | 国内模型大多兼容 OpenAI 接口，换 `base_url` 即可切换     |
| python-multipart  | —      | 表单解析        | 若做文件上传才需要                                |

### 2.3 大模型接入

| 项    | 建议                                                                           |
| ---- | ---------------------------------------------------------------------------- |
| 模型   | 通义千问 / DeepSeek / 智谱 GLM / Kimi / 硅基流动，任选一个，**有免费额度就先用免费的**                  |

### 2.6 Vite proxy（联调的关键，别漏）

```ts
// vite.config.ts
export default defineConfig({
  server: {
    proxy: {
      '/api': { target: 'http://127.0.0.1:8000', changeOrigin: true }
    }
  }
})
```

> 配了 proxy，前端请求 `/api/xxx` 会被转发到后端 8000 端口，**根本不产生跨域问题**。这比配 CORS 省事得多。

## 第 3 章 MVP 功能清单

### 3.1 必须做（6 项，全部完成才算 MVP）

| # | 功能      | 验收标准                                         |
| - | ------- | -------------------------------------------- |
| 1 | 自然语言解析  | 输入中文口语，返回 `{金额, 分类, 日期, 备注, 置信度}`，**只解析不入库** |
| 2 | 预览确认    | 解析结果在前端可编辑，用户点"确认"才入库                        |
| 3 | 账单 CRUD | 新增 / 列表（分页 + 按月筛选 + 按分类筛选）/ 编辑 / 删除          |
| 4 | 统计图表    | 分类饼图 + 6 个月趋势折线，数据**全部来自后端 SQL 聚合**，不在前端算    |
| 5 | 解析容错    | 模型返回非法 JSON 时自动重试 1 次；仍失败返回兜底草稿并提示用户手填       |
| 6 | 幂等去重    | 同一段原文 60 秒内重复提交，不重复入库，返回已有记录                 |

### 3.2 三个加厚工程点（这是简历的肉，不做就是白做）

**① 结构化输出 + 强校验 + 错误回灌重试**

```python
# 伪代码，自己敲
for attempt in range(2):
    raw = await call_llm(prompt if attempt == 0 else prompt + error_feedback)
    try:
        return TransactionDraft.model_validate_json(raw)
    except ValidationError as e:
        error_feedback = f"上次输出不合法：{e.errors()}，请严格按 schema 重新输出"
```

四层防御：JSON Mode 约束格式 → `temperature=0` → Pydantic 校验 → 校验错误回灌重试 → 兜底草稿。

**② 分类枚举 + 月度预算超支提醒**

分类**不要开放增删**（预置 8 类：餐饮/交通/购物/居住/娱乐/医疗/学习/其他）。开放了前端下拉和图表配色都会失控。设一个月度总预算，超了在页面顶部出红色提示——这是"产品感"细节，面试很好讲。

**③ 幂等去重**

`raw_text` + `created_at` 做 60 秒窗口判重。体现你知道"用户会连点两次按钮"这种现实问题。

### 3.3 加分项（学有余力再做）

- 语音输入（浏览器 `SpeechRecognition`，兼容性坑多，**D3 之前别碰**）
- 导出 CSV
- 分类预算（不只是总预算）
- 深色模式

### 3.4 明确不要碰（防半途而废的护栏）

- ❌ 多用户注册登录 / 账本共享（项目二再上 JWT，别重复做）
- ❌ 银行流水 CSV 导入、OCR 拍票据
- ❌ 移动端 App / 小程序
- ❌ 多账本、多币种、汇率换算

## 第 4 章 接口清单

### 4.1 通用约定

| 项         | 约定                                                         |
| --------- | ---------------------------------------------------------- |
| Base Path | `/api`                                                     |
| 内容类型      | `application/json`（除文件上传）                                  |
| 认证        | 本项目**无认证**（单用户本地应用）                                        |

| 日期格式      | `YYYY-MM-DD`（`occurred_on`）、`YYYY-MM`（月份筛选）                |
| 金额        | 数字类型，两位小数，单位元                                              |

### 4.2 接口总表（7 个）

| # | 方法     | 路径                       | 说明                   | 状态码                 |
| - | ------ | ------------------------ | -------------------- | ------------------- |
| 1 | POST   | `/api/parse`             | 解析口语文本，**不落库**       | 200 / 422           |
| 2 | POST   | `/api/transactions`      | 创建账单（可带判重）           | 201 / 200(重复) / 422 |
| 3 | GET    | `/api/transactions`      | 列表（分页 + 筛选）          | 200                 |
| 4 | PATCH  | `/api/transactions/{id}` | 部分更新                 | 200 / 404           |
| 5 | DELETE | `/api/transactions/{id}` | 删除                   | 204 / 404           |
| 6 | GET    | `/api/stats/monthly`     | 月度统计（分类汇总 + 趋势 + 预算） | 200                 |
| 7 | GET    | `/api/categories`        | 分类字典（含配色）            | 200                 |



### 4.4 错误码约定

| 状态码 | 场景                             |
| --- | ------------------------------ |
| 400 | 参数格式错误（如 `month` 不是 `YYYY-MM`） |
| 404 | 账单不存在                          |
| 422 | 校验失败（含 LLM 解析失败）               |
| 500 | 服务端异常（LLM 超时、数据库错误）            |

## 第 5 章 里程碑（7 天）

> **每天结束必须有"能看见的东西"**。做不到就不进下一天。

### D1 · 搭骨架（AI 占比 20%）

| 项    | 内容                                                                                                  |
| ---- | --------------------------------------------------------------------------------------------------- |
| 任务   | ① `npm create vite` 建 Vue 项目 ② 建 FastAPI 项目，写 `/api/ping` ③ 配 Vite proxy ④ 前端页面请求 `/api/ping` 并显示结果 |
| 验收   | 浏览器页面显示 `pong`                                                                                      |
| 卡住预案 | 页面 404 → 先确认后端 `http://127.0.0.1:8000/api/ping` 在浏览器能打开；能打开但前端 404 → proxy 没配或路径少了 `/api`           |
| 心态   | **今天的产出不是功能，是"我能掌控"的感觉。** 别急着写业务                                                                    |

### D2 · 纯 CRUD，不接 LLM（AI 占比 20%）

| 项    | 内容                                                                                                                   |
| ---- | -------------------------------------------------------------------------------------------------------------------- |
| 任务   | ① 建 3 张表 ② `POST/GET /api/transactions` ③ Swagger 里手动传参验证                                                            |
| 验收   | `/docs` 里能成功创建一条账单，能查回来                                                                                              |
| 卡住预案 | `MissingGreenlet` → 检查是否用了 `create_async_engine` + `async_sessionmaker(expire_on_commit=False)`，关系加载用 `selectinload` |
| 心态   | **故意不接 LLM。** 新手最常见的死法是一上手同时调前端+后端+大模型，报错了不知道哪层的问题                                                                   |

### D3 · 接 LLM + 校验 + 重试（AI 占比 40%）

| 项    | 内容                                                                 |
| ---- | ------------------------------------------------------------------ |
| 任务   | ① `llm.py` 封装调用 ② `TransactionDraft` Pydantic 模型 ③ 校验失败回灌重试 ④ 兜底草稿 |
| 验收   | 准备 **20 条中文口语样本**，`/api/parse` 成功率 ≥ 90%（分类正确 + 金额正确 + 日期合理）       |
| 卡住预案 | 模型返回带 ` ```json ` 包裹 → 开 JSON Mode + 正则剥壳兜底                        |
| 产出   | **把这 20 条样本和成功率记下来**，这就是简历上的数字                                     |

### 6.1 数据模型（DDL）

```sql
CREATE TABLE transactions (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  amount      NUMERIC(10,2) NOT NULL,     -- 必须 Numeric，不能用 Float
  category    VARCHAR(20)   NOT NULL,
  occurred_on DATE          NOT NULL,     -- 必须 Date，按月亮片图全靠它
  note        VARCHAR(200),
  raw_text    TEXT,                       -- 原始口语，用于判重和排查
  source      VARCHAR(10)   NOT NULL,     -- 'llm' | 'manual'
  created_at  DATETIME      NOT NULL
);
CREATE INDEX ix_tx_occurred ON transactions(occurred_on);
CREATE INDEX ix_tx_category ON transactions(category);

CREATE TABLE categories (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  name      VARCHAR(20) NOT NULL UNIQUE,
  icon      VARCHAR(20),
  color     VARCHAR(10)          -- 给 ECharts 图例配色，前后端共用
);

CREATE TABLE budgets (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  month       CHAR(7) NOT NULL,   -- '2026-11'
  amount      NUMERIC(10,2) NOT NULL,
  category_id INTEGER REFERENCES categories(id)
);
```

**两个必踩的字段类型坑**（写进 README，面试也会问）：

| 坑             | 后果                                          | 正确做法            |
| ------------- | ------------------------------------------- | --------------- |
| 金额用 `Float`   | `0.1 + 0.2 = 0.30000000000000004`，几百条后总额差几毛 | `Numeric(10,2)` |
| 日期用 `VARCHAR` | 按月 `GROUP BY` 要写 `substr()`，且走不了索引          | `Date` 类型       |

### 6.3 核心链路：解析 → 确认 → 入库

```
前端 axios.post('/api/parse', {text})
   ↓
后端拼 prompt（temperature=0 + JSON Mode + 2 个 few-shot）
   ↓
LLM 返回 → Pydantic 校验 → 失败回灌重试 1 次 → 仍失败返回 422 + 兜底草稿
   ↓
前端表单预填（用户可改）
   ↓
用户点确认 → POST /api/transactions → 入库（含 60s 判重）
   ↓
前端重新拉 GET /api/transactions + GET /api/stats/monthly
```

**为什么解析和入库要分两次请求？**  
模型准确率做不到 100%，一旦错了就是脏数据，用户还得去删。加一步人工确认，成本极低，但数据质量和信任度都上来了。**这是本项目最有价值的架构决策，面试主动讲。**

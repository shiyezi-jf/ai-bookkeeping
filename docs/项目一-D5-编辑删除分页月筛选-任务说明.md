# D5 · 编辑 / 删除 / 分页 / 月筛选 · 任务说明

> 项目：项目一 · AI 一句话记账（Vue3 + FastAPI + SQLite）
> 阶段：D5（AI 占比参考 50%）
> 本文档是 D5 的唯一执行依据：目标、范围、步骤、契约、验收标准均以本文为准。

## 一、任务目标

D4 完成的是"能记账"的单向链路：输入一句话 → 解析 → 确认 → 入库 → 列表出现。

D5 要把这条链路补成"能管账"：

| 能力 | 业务含义 |
| --- | --- |
| 编辑 | 记错了能改，不用删了重记 |
| 删除 | 不想要的记录能清掉，且不会误删 |
| 分页 | 账多了能一页页翻，不会一次加载全部 |
| 月筛选 | 只看某个月的账 |

这四个功能共用同一个底层改造：**把列表接口从"固定全量查询"改成"按参数取数"**。

## 四、接口契约（必须严格遵守）

### 4.1 `GET /api/transactions` —— 列表（分页 + 月筛选）

**请求参数（全部为查询参数）**

| 参数 | 类型 | 必填 | 默认 | 约束 |
| --- | --- | --- | --- | --- |
| `page` | int | 否 | `1` | 最小 `1` |
| `size` | int | 否 | `10` | 最小 `1`，最大 `100`（超出上限需被限制或拒绝，不得原样放行） |
| `month` | str | 否 | 无 | 格式 `YYYY-MM`，如 `2026-11` |

**筛选规则**

- 传了 `month`：只返回 `occurred_on >= 当月 1 日` 且 `occurred_on < 次月 1 日` 的记录。
- 未传 `month`：不按时间筛选。
- 禁止用 `LIKE` / `substr()` 做月份匹配，必须用日期范围比较，以命中 `ix_tx_occurred` 索引。
- 跨年边界必须正确：`2026-12` 的次月是 `2027-01`。

**响应结构**

```json
{
  "items": [ /* TransactionRead 数组 */ ],
  "total": 87,
  "page": 1,
  "size": 10
}
```

**关键约束**

1. `total` 与 `items` 必须使用**完全相同的筛选条件**，否则分页页数会算错。
2. `total` 是满足筛选条件的总条数，不是当前页条数，也不是全库条数（传了 `month` 时）。
3. 排序规则保持 `occurred_on DESC, id DESC`。
4. 分页必须在数据库层完成（`LIMIT` / `OFFSET`），不得全量查出后在 Python 中切片。

**错误响应**

| 场景 | 状态码 |
| --- | --- |
| `month` 格式非法（如 `2026-13`、`abc`） | `400` |
| `page` / `size` 越界 | `400` 或 `422`（二者择一，需在实现中固定） |

### 4.2 `PATCH /api/transactions/{id}` —— 部分更新

**请求体**：仅包含要修改的字段，所有字段均可选。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `amount` | Decimal | 可选；传入时必须 `> 0`，`max_digits=10`，`decimal_places=2` |
| `category` | Literal | 可选；仅限 餐饮 / 交通 / 购物 / 居住 / 娱乐 / 医疗 / 学习 / 其他 |
| `occurred_on` | date | 可选；格式 `YYYY-MM-DD` |
| `note` | str \| null | 可选；最长 200 |

**行为要求**

1. **只更新请求体中出现的字段**，未出现的字段保持原值（`exclude_unset` 语义）。
2. 必须新建独立的更新模型（不得复用 `TransactionCreate`），否则"只改备注"会被判为非法请求。
3. `id` 不存在 → `404`。
4. 成功 → `200`，响应体为更新后的 `TransactionRead`。

### 4.3 `DELETE /api/transactions/{id}` —— 删除

| 场景 | 行为 |
| --- | --- |
| 记录存在 | 硬删除，返回 `204`，无响应体 |
| 记录不存在 | 返回 `404` |
| 重复删除同一 `id` | 第二次返回 `404` |

> 采用硬删除。理由是单用户本地应用，软删除会给后续所有查询附加过滤条件，收益不成立。

### Step 1 · 后端列表升级（分页 + 月筛选）

**改动文件**

- `backend/app/schemas.py`：新增分页响应模型（含 `items`、`total`、`page`、`size`）
- `backend/app/routers/transactions.py`：改造 `list_transactions`

**交付要求**

- 接口契约完全符合 4.1。
- 修改 `response_model`，使其与新返回结构一致。
- 非法 `month` 必须在进入业务逻辑前被拦截，返回 `400`，不得抛出 `500`。

**自测清单**

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | 不传参数 | 返回第 1 页、最多 10 条，`total` 等于真实总数 |
| 2 | `page=2&size=2` | `items` 为第 3、4 条，且与第 1 页不重复 |
| 3 | `month=2026-11` | `items` 全为 11 月记录，`total` 为 11 月条数 |
| 4 | `month=2026-13`、`month=abc` | 返回 `400` |
| 5 | `size=9999` | 被限制在 100（或返回 `400`/`422`），不得返回 9999 条 |
| 6 | `month=2026-12`（若存在跨年数据） | 能正确取到 12 月记录，不包含次年 1 月 |

**已知副作用**

本步完成后，前端列表会因返回结构变化而报错。这是预期现象，**不得在本步回头修改前端**，统一在 Step 4 处理。

### Step 4 · 前端改造

> 本步分为 5 个子块，按序完成。

**4.0 安装依赖**

- 安装 Element Plus 并在 `main.ts` 中接入。

**4.1 API 层改造**（`frontend/src/api/index.ts`）

| 函数 | 要求 |
| --- | --- |
| `listTransactions` | 接收 `page`、`size`、`month` 参数，返回分页对象类型 |
| `updateTransaction` | 接收 `id` 与部分字段，返回更新后的记录 |
| `deleteTransaction` | 接收 `id`，无返回数据 |

- 新增与后端响应对应的分页类型定义。
- 错误处理沿用现有 `request` / `toMessage` 机制，不另起一套。

**4.2 列表操作列**（`frontend/src/views/Home.vue`）

- 每行增加"编辑"、"删除"两个操作入口。

**4.3 弹窗编辑**

- 点击"编辑"打开弹窗，表单预填当前行数据。
- 字段：金额、分类、日期、备注，校验规则与 D4 确认卡片保持一致（金额 > 0、分类必选、日期必选）。
- 保存成功后关闭弹窗，并重新请求列表。
- 保存失败时弹窗不关闭，保留用户已填内容并展示错误。

**4.4 删除二次确认**

- 点击"删除"必须先弹出确认，用户确认后才发起请求。
- 删除成功后重新请求列表。

**4.5 分页 + 月份切换**

- 分页组件使用后端返回的 `total` 计算总页数，不得用当前页条数推算。
- 切换月份时必须将 `page` 重置为 `1`，再请求。
- **空页处理**：删除后若 `items.length === 1` 且 `page > 1`，则先 `page--` 再请求；删除后若列表为空且 `page === 1`，正常展示空状态。

**统一要求：所有写操作（编辑、删除）成功后一律重新请求列表，不得在前端数组上手动增删改。以服务端返回为准。**

**自测清单**

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | 打开编辑弹窗 | 四个字段预填当前行数据 |
| 2 | 只改备注保存 | 列表该行备注更新，其他字段不变 |
| 3 | 编辑时把金额清空 | 保存按钮不可用，并提示原因 |
| 4 | 删除一条 | 先弹确认；取消则不发请求；确认后列表少一条 |
| 5 | 翻到第 2 页删除该页最后一条 | 自动回到第 1 页（或上一页），不停留在空页 |
| 6 | 切换到上个月 | 页面回到第 1 页，列表只显示该月数据 |
| 7 | 切月后翻页 | 分页状态下数据仍限定在该月内 |
| 8 | 月份清空 | 恢复全部数据、第 1 页 |

## 六、交付标准

### 6.1 功能交付

- [ ] `GET /api/transactions` 支持 `page`、`size`、`month`，返回 `{items, total, page, size}`
- [ ] `total` 与筛选条件严格一致
- [ ] `PATCH /api/transactions/{id}` 支持部分更新，未传字段不被覆盖
- [ ] `DELETE /api/transactions/{id}` 成功返回 `204`，重复删除返回 `404`
- [ ] 前端完成"翻页 → 切月 → 编辑 → 删除 → 回第 1 页"完整闭环
- [ ] 编辑失败、删除失败均有可见的错误提示
- [ ] 删除当前页最后一条后不停留在空页

### 6.2 质量要求

- [ ] 所有接口均可在 `/docs` 中独立验证通过
- [ ] 分页在数据库层完成，未使用全量查询后切片
- [ ] 月份筛选使用日期范围比较，未使用 `LIKE` / `substr()`
- [ ] 金额字段未出现 `float` 运算
- [ ] 前端未出现"手动改本地数组"的写操作
- [ ] `size` 上限生效，无法通过参数拉取全表

### 6.3 最终验收动作（按序执行，全部通过才算 D5 完成）

1. 在 `/docs` 中依次验证三组用例：分页、非法月份、部分更新。
2. 浏览器中执行：切到指定月份 → 翻到第 2 页 → 编辑一条并保存 → 删除该页最后一条 → 确认页面未停留在空页。
3. 编辑一条金额，刷新浏览器，确认修改已持久化。
4. 删除一条，刷新浏览器，确认记录不再出现。
5. 清空月份筛选，确认恢复全量数据且 `page` 为 1。

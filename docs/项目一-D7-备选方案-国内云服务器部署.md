# 项目一 · D7 备选方案：国内云服务器部署（不用信用卡）

> **为什么换这条路**：Render 只收 Visa / Mastercard，邮储的银联卡过不了那道验证。这条路**只需要支付宝**，一年几十到一百多块，换来三个好处：
>
> - **数据永久保留**（就是你自己的服务器，不会因为重新部署被清空）
> - **国内打开秒开**，面试官不用等 50 秒冷启动
> - **不用绑卡、不用翻墙、不用备案**
>
> **你会得到**：`http://你的服务器IP:8080` —— 一个前后端都在这台机器上的完整网站。
>
> **需要多久**：买机器 10 分钟 + 部署 15 分钟 + 验证 15 分钟。

---

## 先弄清一件事：为什么前端也搬到服务器上

原方案是"前端放 Vercel + 后端放 Render"，两个不同的网站。现在后端变成了 `http://IP:8080`（没有 https），如果前端还放在 Vercel（`https://xxx.vercel.app`），浏览器会拦住前端对后端的请求——这条规矩叫"混合内容拦截"，`https` 的页面不允许调用 `http` 的接口。

**所以这次前端和后端都放在同一台服务器上，用同一个端口。** 浏览器看到的永远是同一个地址，跨域问题、混合内容问题一次性全没了。

> 这也意味着：**这次不需要 Vercel 了。** 之前部署的 Vercel 项目可以留着不管，也可以去 Vercel 后台删掉，不影响任何东西。

```
浏览器
  └── http://IP:8080            ← nginx 对外只开这一个端口
        ├── /            前端静态文件（Vite 构建出来的 dist）
        └── /api/...     转发给本机 127.0.0.1:8000 的 FastAPI
                              └── app.db（数据就存在这台机器上）
```

## 整体流程（6 步）

```
① 买服务器（选 Ubuntu 22.04）     约 10 分钟
② 防火墙放行 8080 端口             约 2 分钟
③ 用 SSH 连上服务器                约 3 分钟
④ 跑一条部署命令                   约 10 分钟（其中大部分是等待）
⑤ 打开网址验证                     约 5 分钟
⑥ 完整验收                         约 10 分钟
```

## 第 1 步 · 买一台服务器

**你要做什么**：在腾讯云或阿里云买一台最便宜的"轻量应用服务器"。**两家随便选一家，步骤几乎一样**，下面的说明两家都适用。

### 1.1 进入购买页

- 腾讯云：浏览器打开 `https://cloud.tencent.com` → 顶部菜单 **产品** → 搜 **轻量应用服务器** → 点 **立即选购**
- 阿里云：浏览器打开 `https://www.aliyun.com` → 搜 **轻量应用服务器** → 点 **立即购买**

### 1.2 按下面这张表逐项选（**每一项都要对**）

| 选项 | 选什么 | 为什么 |
| --- | --- | --- |
| **地域** | 国内任选（上海 / 广州 / 北京 / 成都） | 国内访问最快。**除非**你以后想绑域名用 80 端口，才选"香港" |
| **镜像 / 系统** | **Ubuntu 22.04 LTS**（有的显示 `Ubuntu 22.04`） | 🔴 **必须是这个**，脚本只支持 Ubuntu。选错（CentOS / Debian / 宝塔面板）会直接失败 |
| **套餐 / 配置** | **2 核 2G**（最低 1 核 2G 也行） | 构建前端要内存，1 核 1G 容易卡死 |
| **系统盘** | 40G 或以上 | 默认就够 |
| **时长** | 1 年（年付最便宜） | 按月也行，但年付通常打折 |
| **登录方式** | 设置密码（**不是**"密钥对"） | 后面用密码 SSH 登录，最简单 |

> 💡 **省钱提示**：腾讯云有"云+校园"、阿里云有"飞天加速计划"，学生认证后能便宜很多。认证需要学信网/学生证，认证流程 1–2 天，**如果你赶时间就别等，直接买普通套餐**。

### 1.3 付款

选 **支付宝** → 扫码付款。**不需要信用卡。**

### 1.4 设置 root 密码（关键，别漏）

付完款后：

1. 进入控制台 → 找到刚买的服务器 → 点服务器名字进入**详情页**。
2. 找到 **重置密码**（腾讯云在"概要"里，阿里云在"实例"操作菜单里）→ 点它。
3. 输入一个**你自己记得住的强密码**（建议：大写字母 + 小写字母 + 数字 + 符号，12 位以上，例如 `Abk2026@server`）。
4. 确认重置。有的平台会要求重启服务器生效，按提示重启。

**你应该看到**：详情页上有一个 **公网 IP**，形如 `123.45.67.89`。

**✅ 本步通过标准**：

1. 你手上有两样东西：**公网 IP**（一串数字和点）和 **root 密码**（你自己刚设的）
2. 服务器状态是"运行中"

**⚠️ 卡住了怎么办**：

| 现象 | 怎么办 |
| --- | --- |
| 找不到"重置密码" | 在控制台搜索框输入"重置密码"，或在实例列表的"更多/操作"菜单里找 |
| 买完发现选成了 CentOS | 在控制台给服务器**重装系统**，选 Ubuntu 22.04（数据会清空，此时还没数据，无所谓） |
| 提示需要实名认证 | 按提示用支付宝/微信做个人实名，10 分钟能过 |

## 第 2 步 · 放行 8080 端口（不做这步网站一定打不开）

**你要做什么**：告诉云厂商"允许外面的人访问 8080 端口"。

> 云服务器默认只开 22（远程登录）等少数端口，8080 是关着的。**这一步是新手最容易漏、漏了最难查的一步**——表现是：服务器上一切正常，但浏览器就是打不开。

**动手（腾讯云轻量）**：

1. 控制台 → 点进服务器详情页。
2. 点上方标签 **防火墙**。
3. 点 **添加规则**。
4. 按下表填：

   | 字段 | 填什么 |
   | --- | --- |
   | 应用类型 | 自定义 |
   | 协议 | **TCP** |
   | 端口 | **8080** |
   | 来源 | 全部（`0.0.0.0/0`） |
   | 备注 | ai-bookkeeping |

5. 点 **确定**。

**动手（阿里云轻量）**：

1. 控制台 → 点进服务器详情页。
2. 点 **防火墙** 标签 → **添加规则**。
3. 应用类型选 **自定义**，协议 **TCP**，端口范围填 **8080**，授权对象填 `0.0.0.0/0`。
4. 点 **确定**。

**你应该看到**：防火墙规则列表里多出一条 `TCP 8080`。

**✅ 本步通过标准**：规则列表里能看到 `8080` 这一条，且状态是"生效/已启用"。

**⚠️ 卡住了怎么办**：

- 找不到"防火墙" → 在控制台搜索框里输入"防火墙"。
- 阿里云 ECS（不是轻量）→ 那叫"**安全组**"，在实例详情 → 安全组 → 配置规则 → 入方向 → 手动添加。

## 第 3 步 · 连上服务器

**你要做什么**：从你自己的电脑"远程登录"到这台服务器，之后所有命令都在服务器上敲。

**动手**：

1. 打开 **Git Bash**（就是你之前一直用的那个黑窗口）。
2. 输入下面这行，把 IP 换成你自己的，然后回车：

```bash
ssh root@123.45.67.89
```

3. 第一次连接会问：

```
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

   输入 `yes` 并回车（**必须打完整的 yes，不能只打 y**）。

4. 然后提示 `root@123.45.67.89's password:`，输入你第 1.4 步设的密码，**回车**。

> 🔴 **注意**：输密码时屏幕上**一个字都不会显示**，连星号都没有。这是正常的，不是卡住了。直接输完按回车即可。

**你应该看到**：命令行提示符变成类似这样：

```
root@VM-0-15-ubuntu:~#
```

**✅ 本步通过标准**：提示符里有 `root@` 和 `#`，并且**不再是** `jiafa@...MINGW64`。

**⚠️ 卡住了怎么办**：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `Connection timed out` | 22 端口被拦或 IP 写错 | 检查 IP；确认防火墙里 22 端口是开的（默认就开着） |
| `Permission denied` | 密码错 | 回第 1.4 步重新重置密码，注意大小写和特殊字符 |
| `ssh: command not found` | 没装 SSH 客户端 | Git Bash 自带，确认你打开的是 Git Bash 而不是 cmd |
| 一直卡住不动 | 网络问题 | 按 `Ctrl + C` 中断，重试一次 |

## 第 4 步 · 跑一条命令完成部署

**你要做什么**：把仓库里已经写好的部署脚本下载到服务器上并执行。**脚本会自动完成安装 Python、装依赖、配置开机自启、构建前端、配置 nginx 全部工作。**

### 4.1 执行部署命令

在服务器上（提示符是 `root@...#`）粘贴下面这三行，**一次全部粘进去**，回车：

```bash
apt-get update -y && apt-get install -y git
git clone --depth 1 https://github.com/shiyezi-jf/ai-bookkeeping.git /tmp/abk
sudo bash /tmp/abk/deploy/deploy.sh
```

> 第 1 行装 git（服务器上通常已经有了，重复装无害）；第 2 行只下载代码，不带历史记录，很快；第 3 行执行部署脚本。

**如果 `git clone` 卡住超过 1 分钟没动静**（国内访问 GitHub 偶尔会这样），改用下面这条：直接下载脚本文件，不用 git：

```bash
curl -fsSL https://raw.githubusercontent.com/shiyezi-jf/ai-bookkeeping/main/deploy/deploy.sh -o deploy.sh && sudo bash deploy.sh
```

> 这条命令我在国内网络实测过，`raw.githubusercontent.com` **经常连不上**（会卡住直到超时）。所以**优先用上面那三行**，这条只作为备用。

**两条都失败怎么办**（说明这台机器访问 GitHub 有问题）：在**你自己电脑**的 Git Bash 里执行下面这行，把脚本直接传上去（把 IP 换成你的）：

```bash
scp deploy/deploy.sh root@123.45.67.89:/root/deploy.sh
```

传完后在**服务器上**执行：

```bash
sudo bash /root/deploy.sh
```

> `scp` 需要在项目根目录 `D:\Code\My_Project\ai-bookkeeping` 下执行，路径才是对的。

### 4.2 中途会停下来问你密钥

脚本跑到第 3 步会显示：

```
请粘贴你的 DeepSeek 密钥（sk- 开头，粘贴后按回车，屏幕上不会显示）：
```

**动手**：在窗口里**点鼠标右键 → Paste**（或 `Shift + Insert`），把 `sk-` 开头的密钥粘进去，然后回车。同样，屏幕上不会显示任何字符。

> 如果还没有密钥，先去 `https://platform.deepseek.com` 创建一个（详细步骤见主文档第 5 步）。

### 4.3 等它跑完

屏幕上会依次出现：

```
==== 0/8 环境检查 ====
==== 1/8 安装系统依赖 ====
==== 2/8 拉取代码 ====
...
==== 8/8 自检 ====
后端直连  : {"message":"pong"}
nginx 转发: {"message":"pong"}
```

最后出现：

```
🎉 部署完成
  网站地址：http://123.45.67.89:8080
  接口文档：http://123.45.67.89:8080/docs
```

**整个过程 5–10 分钟**，其中"安装系统依赖"和"构建前端"各要等 1–3 分钟，屏幕不动是正常的。

**✅ 本步通过标准**：

1. 看到 **🎉 部署完成**
2. 看到 `后端直连 : {"message":"pong"}` 和 `nginx 转发: {"message":"pong"}` 两行
3. 记下打印出来的**网站地址**

**⚠️ 卡住了怎么办**：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `❌ 这个脚本只支持 Ubuntu` | 买成了 CentOS/Debian | 控制台重装系统为 Ubuntu 22.04，重跑 |
| `Node.js 下载失败` | 网络抖动 | 直接**再执行一次**同一条命令，脚本可重复运行 |
| `❌ 后端启动失败` + 一堆日志 | 多半是密钥或数据库问题 | 把最后 30 行日志复制给 AI |
| `❌ 前端构建失败` | 内存不足 | 换 2 核 4G，或在服务器上手动 `cd /opt/ai-bookkeeping/frontend && npm run build` 看具体报错 |
| 密钥粘贴进去提示"不像一个密钥" | 粘贴时带上了空格或换行 | 重新执行命令，重新粘贴，注意不要多按回车 |
| 中途网络断了 | SSH 断开 | 重新 SSH 连上，**再执行一次同一条命令**即可，脚本会跳过已完成的部分 |

> 📌 **记住一点**：这个脚本可以反复执行，不会搞坏东西。任何一步失败，修好原因后再跑一次就行。

## 第 5 步 · 打开网址，确认真的活了

**你要做什么**：用浏览器访问，做第一次真实验收。

**动手**：

1. 浏览器打开 `http://你的IP:8080`（**注意是 http，不是 https**；端口是 8080）。
2. 按 `F12` 打开开发者工具 → **Console** 标签。
3. 刷新页面（`F5`）。

**你应该看到**：

- 页面完整显示：输入框、"解析"按钮、账单列表（空的）、分类饼图、6 个月趋势折线
- Console 里**没有**红色报错
- 再点 **Network** 标签，能看到 `/api/...` 的请求，状态码 `200`

**动手（再验证接口文档）**：浏览器打开：

```
http://你的IP:8080/docs
```

应该看到紫色的接口文档页，标题是 **AI 一句话记账 API**。

**✅ 本步通过标准**（三条全中）：

1. 页面正常显示，没有空白页、没有一直转圈
2. `http://IP:8080/docs` 能打开
3. Console 里没有红字

**⚠️ 卡住了怎么办**：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 浏览器显示"无法访问此网站" | **90% 是防火墙没放行 8080** | 回第 2 步，确认规则存在；改完规则**立即生效**，不用重启 |
| 显示 nginx 的 "Welcome to nginx" | 默认站点没删掉 | 服务器上执行 `rm -f /etc/nginx/sites-enabled/default && systemctl reload nginx` |
| 页面打开是白屏 | 前端没构建成功 | 服务器上执行 `ls /opt/ai-bookkeeping/frontend/dist`，没有 `index.html` 就重跑脚本 |
| 页面能开但数据空、Console 报 404 | nginx 没转发 `/api` | 执行 `nginx -t` 看配置；确认 `/etc/nginx/sites-enabled/ai-bookkeeping` 存在 |
| 502 Bad Gateway | 后端没起来 | `systemctl status ai-bookkeeping`，再 `journalctl -u ai-bookkeeping -n 50` |

## 日常维护（以后会用到）

### 改完代码怎么更新线上

```bash
# 1. 你本地改完代码后
git add .
git commit -m "改了什么"
git push

# 2. SSH 登录服务器，执行
sudo bash /opt/ai-bookkeeping/deploy/update.sh
```

`update.sh` 会自动拉最新代码、同步依赖、重建前端、重启后端，并做一次健康检查。

### 常用命令（SSH 登录后执行）

| 想干什么 | 命令 |
| --- | --- |
| 实时看后端日志 | `journalctl -u ai-bookkeeping -f`（按 `Ctrl + C` 退出） |
| 看最近 50 行日志 | `journalctl -u ai-bookkeeping -n 50` |
| 重启后端 | `systemctl restart ai-bookkeeping` |
| 重启 nginx | `systemctl reload nginx` |
| 看后端状态 | `systemctl status ai-bookkeeping` |
| 改密钥 | `nano /opt/ai-bookkeeping/backend/.env`，改完 `systemctl restart ai-bookkeeping` |

### 备份数据（建议每周一次）

在你**自己电脑**的 Git Bash 里执行（把 IP 换成你的）：

```bash
scp root@123.45.67.89:/opt/ai-bookkeeping/backend/app.db ./app-backup-$(date +%F).db
```

这会把服务器上的数据库文件下载到你当前目录。**这一个文件就是你全部账单**，丢了就没了。

## 常见问题

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 网站打不开，服务器上 `curl localhost:8080` 正常 | 云厂商防火墙没放行 8080 | 回第 2 步加规则 |
| 服务器重启后网站 502 | 后端没设开机自启 | 执行 `systemctl enable ai-bookkeeping` |
| 点"解析"报错，其他功能正常 | `LLM_API_KEY` 错或余额不足 | 改 `/opt/ai-bookkeeping/backend/.env`，重启服务；去 DeepSeek 后台看余额 |
| 页面样式错乱 | 浏览器缓存 | `Ctrl + F5` 强刷 |
| 构建时卡在 `npm ci` | 国内访问 npm 慢 | 在服务器执行 `npm config set registry https://registry.npmmirror.com` 后重跑 |
| `git clone` 卡住不动 | GitHub 网络问题 | 重试；或把脚本用 `scp` 传上去手动执行 |
| 想换端口（8080 → 其他） | —— | `sudo PORT=9090 bash /opt/ai-bookkeeping/deploy/deploy.sh`，记得同步改防火墙 |

## 关于"想要 https 的漂亮链接"（可选，现在不用做）

`http://IP:8080` 完全够用，面试官点开就能看。如果你以后想要 `https://xxx.com` 这种，需要两样东西：

1. **一个域名**：几十元/年，在阿里云/腾讯云买。
2. **备案**：域名指向**国内**服务器时，用 80/443 端口必须先备案（免费，但要 1–3 周，需要身份证+拍照）。

**省事的替代**：把服务器换成**香港/新加坡**节点（略贵，且免备案），绑域名后用 `certbot` 免费申请证书，10 分钟就能上 https。脚本支持改端口：`sudo PORT=80 bash deploy.sh`。

**现在不建议折腾。** 先把项目跑通、README 写好、简历投出去，https 是锦上添花，不是必需品。
